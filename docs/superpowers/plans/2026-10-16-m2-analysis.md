# M2 Game Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import the user's chess.com games and review any game on the phone. The review shows win-chance and accuracy, labels every move from Brilliant to Blunder, explains each mistake from engine facts in plain words, and walks through key moments with Retry and Follow-up. Mistakes are added up across games.

**Architecture:** All logic lives in `ChessCoachKit`:
- `Analysis/WinChance.swift`: the formulas.
- `Analysis/MoveClassifier.swift`: classification rules.
- `Analysis/Attacks.swift` + `Analysis/FactExtractor.swift`: deterministic chess facts.
- `Analysis/Explainer.swift`: template text.
- `Analysis/GameAnalyzer.swift`: per-ply engine pass with cache and progress telemetry.
- `Import/ChessComClient.swift` + `Import/ChessComImporter.swift`.
- `Persistence` migration v2.

The app adds `Features/Analyze/ImportButton`, `ReviewScreen`, `EvalGraph`, `CoachBubble` and `RecurringMistakesView`.

**Tech Stack:** as M1, plus URLSession (an injected `HTTPClient` protocol for tests).

**Spec:** §4 (all), §8 tables `position_cache`, `move_analysis`, `motif`, `fact_sheet`, `explanation`, §9 telemetry, §10 errors.

## Tasks

1. **WinChance + accuracy**
   - What it covers:
     - `winPercent(cp:)`, using the cp clamp ±1000 and mate = ±100 (from the mover's perspective)
     - `moveAccuracy(winBefore:winAfter:)`
     - `gameAccuracy(winPercents:color:)`, as volatility-weighted mean + harmonic mean, /2
   - Tests are anchored to Lichess reference values (cp 0 → 50; cp 100 → ≈59.1; accuracy for a 0 drop ≈100; for a 10-point drop ≈64.3 per the formula).
2. **MoveClassifier**
   - Input: `PlyEval` with these fields:
     - fenBefore, played uci/san, mover
     - best lines (MultiPV ≤3, scores from the mover's view, before the move)
     - score after the move (from the mover's view)
     - legal move count
     - isBook
     - Maia probability (optional)
     - material sacrificed flag
     - the opponent's previous EP loss
   - Output: `MoveClass`, one of brilliant, great, best, excellent, good, book, forced, inaccuracy, mistake, miss, blunder.
   - Rules are the spec §4 table plus the "already decided" guard.
   - Tests: one per label, plus the guards.
3. **Attacks + FactExtractor**
   - `Attacks`: attackers(of:by:in:) by ray casting, `isDefended`, `SEE` (a static exchange evaluation (SEE) on one square).
   - `FactExtractor.facts(before:move:bestLine:punishLine:)` returns `FactSheet` with these fields:
     - materialDelta
     - hangingAfter: pieces of the mover that are attacked and not defended, or defended by less than the attacker gains
     - threatsCreated
     - missedCapture (the best line starts with a capture winning ≥2)
     - motifs: fork, pin, skewer, discoveredAttack, backRank, mateThreat, hangingPiece, trappedPiece, mateInN
     - phase
   - Tests run over a golden set of about 25 FENs.
4. **Explainer (templates)**
   - `FactSheet` + `MoveClass` → 1–2 sentences, with no LLM.
   - Tests: every motif has a template; every square or SAN in the output appears in the facts.
5. **Persistence v2**
   - Tables: `position_cache`, `move_analysis`, `motif`, `fact_sheet`, `explanation`.
   - Game columns: `url`, `whiteElo`, `blackElo`, `endReason`.
   - Stores: `AnalysisStore` (save/load a game's analysis, cache lookups) and `MistakeStats` (aggregate by motif × mistake type × phase).
6. **GameAnalyzer**
   - For each position: an `EngineHost` search at depth 14 with MultiPV 3, cached by `fenKey` (FEN without the move counters).
   - Emits telemetry `analysis.game` with progress per ply and an `analysis.ply` child step.
   - It is cancellable and resumes from cached plies.
   - Produces `GameAnalysis` (per-ply `MoveAnalysis` + accuracies + key moments).
   - Maia probability for the Brilliant check comes from the 1100 policy, computed only for candidate brilliants to save time.
7. **ChessComClient + Importer**
   - Requests go through `HTTPClient` and run in order: `/pub/player/{u}/games/archives`, then the months, newest first.
   - User-Agent: `ChessCoach-iOS (personal; github.com/rishi-zamvar/ChessCoach-iOS)`.
   - ETag / If-Modified-Since for the current month; back off on 429.
   - Filters:
     - rules == chess
     - standard start
     - more than 2 plies
     - excludes daily games
     - dedupes by URL
     - lowercase usernames
   - Fixture-driven tests.
8. **Review UI**
   - `ReviewScreen` (dark chrome):
     - eval graph
     - accuracy for each side
     - classification counts (icons drawn in the app, not chess.com's)
     - phase grades
     - "Start Review" key-moment walkthrough with a coach bubble, arrows (green = best, red = the punishing reply)
     - Retry (hint → reveal)
     - Show Follow-up
     - move list with classification dots
   - Progress UI is driven by the telemetry stream and the median ETA.
9. **Analyze tab integration**
   - Import button (username in settings, default `Zammy009`), with an imported/local filter.
   - "Review" on any game; a game played to the end in Play offers Game Review.
   - Recurring Mistakes card.
10. **Verify:**
    - Package tests pass.
    - A golden test on one real imported game: Analyzer output against stored expectations (labels sanity-checked).
    - A UI test: open a game, then run Review.
    - Screenshots, a review agent, then merge to main and tag v0.2.0.
