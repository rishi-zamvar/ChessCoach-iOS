# M1 Base App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sideloadable ChessCoach app with WorkoutCoach-styled 4-tab shell, a chess.com-style board/game screen with sounds and haptics, and offline play against Maia-1100 and Stockfish levels, with every step logged.

**Architecture:**
- All logic lives in the local SPM package `Packages/ChessCoachKit`, tested with `swift test` on macOS for fast iteration. This covers telemetry, persistence, game session, clock, bots, board interaction state and sound mapping.
- The XcodeGen app target `ChessCoach` holds only SwiftUI views, assets and the composition root.
- One `EngineHost` actor owns the single in-process engine. chesskit-engine allows only one engine per process (verified in the M0 spike).

**Tech Stack:** Swift 6 (strict concurrency), SwiftUI, iOS 17, chesskit-swift 0.17, chesskit-engine 0.7 (Stockfish 17 + Lc0 0.31.1), GRDB 7, XcodeGen, XCTest (BDD names).

**Run mode:** autonomous overnight. The plan lists interfaces and test cases per task. Code is written test-first in the task, and each task ends in a commit.

## Tasks

### Task 1: Telemetry core
- **Interfaces:**
  - `StepEvent` is Codable/Sendable with these fields: `id: UUID, runID: UUID, parentID: UUID?, step: String, phase: StepPhase(start|progress|finish|fail), done: Int?, total: Int?, durationMs: Double?, metadata: [String: JSONValue], error: String?, timestamp: Date`.
  - `protocol TelemetrySink: Sendable { func record(_ e: StepEvent) }`
  - `final class Telemetry: Sendable`:
    - `step<T>(_ name: String, parent: StepContext? = nil, metadata: [String: JSONValue] = [:], _ body: (StepContext) async throws -> T) async rethrows -> T`
    - `event(_ name: String, metadata:)` for single-shot events
    - `events: AsyncStream<StepEvent>` (multi-subscriber fan-out)
  - `StepContext` provides `progress(done:total:)` and `annotate(key:value:)`, which adds to the finish metadata.
- **Tests:**
  - given a step that succeeds, when it runs, then the sinks get start + finish with the same runID and durationMs ≥ 0
  - given a throwing body, then start + fail with the error string, and it rethrows
  - given a nested step, then the child's parentID equals the parent's id
  - given progress calls, then progress events carry done/total
  - given a stream subscriber, then it receives events in order
  - given annotate, then the finish metadata includes the value
- **Commit:** `M1: telemetry core`

### Task 2: Persistence (GRDB) + database sink
- **Interfaces:**
  - `AppDatabase(path:)` and `AppDatabase.inMemory()`, built on `DatabasePool`/`DatabaseQueue`.
  - Migrator `v1`:
    - `game(id TEXT PK, source TEXT, pgn TEXT, white TEXT, black TEXT, userColor TEXT, result TEXT, termination TEXT, timeControl TEXT, opponentKind TEXT, startedAt DATETIME, endedAt DATETIME)`
    - `step_event(id TEXT PK, runID TEXT, parentID TEXT, step TEXT, phase TEXT, done INT, total INT, durationMs REAL, metadata TEXT, error TEXT, timestamp DATETIME)` with indexes on `(step, phase)` and `timestamp`
  - `GameStore`: `save(_:)`, `recent(limit:)`, `game(id:)`.
  - `DatabaseSink: TelemetrySink`. It writes on a serial background queue; `prune(olderThan:)` keeps 30 days; `medianDuration(step:) -> Double?` drives ETAs.
- **Tests:**
  - the migration creates the tables
  - save/fetch round-trips a game
  - recent() is ordered by endedAt desc
  - the sink persists events and medianDuration is correct
  - prune removes old rows
- **Commit:** `M1: GRDB persistence + telemetry DB sink`

### Task 3: GameSession, Material, UCI helpers
- **Interfaces:**
  - `GameSession(startFEN: String = standard)` has:
    - `position: Position`, `sideToMove`, `history: [PlayedMove]`, where `PlayedMove` holds `move: Move, san, uci, fenAfter, clockAfter: TimeInterval?`
    - `state: Board.State` and `result: GameResult?`
    - `legalTargets(from:) -> [Square]`
    - `apply(from:to:promotion:) -> ApplyOutcome`, with outcomes `.applied(PlayedMove) | .needsPromotion | .illegal`
    - `apply(uci:)`
    - `resign(color)`, `flag(color)`, `agreeDraw()`
    - `pgn(tags:) -> String`, including `{[%clk h:mm:ss]}` when clocks are present
  - `GameResult` covers winner (Color?), `Termination` (checkmate, resignation, timeout, stalemate, repetition, fiftyMoves, insufficientMaterial, agreement, timeoutVsInsufficientMaterial) and PGN `resultString` ("1-0" / "0-1" / "1/2-1/2").
  - `Material.captured(from history)` returns pieces captured by each side, and `balance(position)` uses pawn=1, minor=3, rook=5, queen=9.
- **Tests:**
  - legal targets of e2 at start = e3, e4
  - Scholar's mate sequence ends with checkmate and White wins
  - illegal move is rejected
  - promotion returns needsPromotion, then apply with promotion succeeds and the SAN ends with "=Q"
  - castling SAN is "O-O"
  - stalemate position detected
  - PGN round-trip parses via `Game(pgn:)`
  - material balance after a capture
  - resign/flag results
  - a flag when the opponent has insufficient material is a draw
- **Commit:** `M1: GameSession + material + UCI`

### Task 4: ChessClock
- **Interfaces:**
  - `TimeControl(base: TimeInterval, increment: TimeInterval)` with presets none / 10|0 / 15|10 / 30|0.
  - `ChessClock(control, now: () -> Date)`: `start(color)`, `press(color)` (adds increment, switches side), `remaining(color, at:)`, `pause()`, `flagged(at:) -> Color?`, `isLow(color, at:)` (under 10% of base or under 20 s).
- **Tests:**
  - time decreases only for the side to move
  - the increment is applied on press
  - flag detection at 0
  - low-time threshold
  - pause stops the countdown
- **Commit:** `M1: chess clock`

### Task 5: MoveSound mapping
- **Interface:** `SoundEvent` (move, capture, castle, check, promote, illegal, premove, gameStart, gameEnd, lowTime) and `SoundEvent.forMove(_ played: PlayedMove, state:) -> SoundEvent`. Priority: gameEnd > check > promote > castle > capture > move.
- **Tests:** one case per event.
- **Commit:** `M1: sound event mapping`

### Task 6: Bots
- **Interfaces:**
  - `protocol BotPlayer: Sendable { var name: String; var rating: Int; func move(for session: snapshot FEN) async throws -> String /*uci*/ }`
  - `MaiaBot(host:, rating: 1100, temperature: Double = 1.0, random: RandomSource)` samples from the policy. Temperature 0 means argmax. It falls back to bestMove if the policy is empty.
  - `StockfishBot(host:, level: BotLevel)`. `BotLevel` presets 1–8 map to Skill Level, depth and movetime, with display ratings of ~400–2000.
  - Every bot move runs inside `telemetry.step("bot.move")` with metadata `{kind, rating, ms}`.
- **Tests:**
  - deterministic sampling with a seeded RNG over a fixed policy
  - temperature 0 picks argmax
  - MaiaBot live: returns a legal move from start
  - StockfishBot level 8 finds mate in 1
- **Commit:** `M1: Maia + Stockfish bots`

### Task 7: Board interaction model + annotations + theme
- **Interfaces:**
  - `BoardInteraction` (struct, pure) has:
    - `selected: Square?`, `legalTargets: [Square]`
    - `premoves: [(Square, Square)]` (max 1 in M1)
    - `tap(square, session, userColor, isUserTurn) -> InteractionResult` with results `.select | .deselect | .move(from,to) | .premoveQueued | .none`
    - `dragBegan/dragEnded`
  - `AnnotationLayer`: `arrows: [Arrow(from,to,color)]`, `highlights: [SquareHighlight(square, kind: lastMove|check|selected|premove|hint)]`, `userArrows` with toggle semantics.
  - `BoardTheme` (light/dark hex, lastMove overlay, check glow) with presets `.green` (default, `#EEEED2`/`#769656`), `.brown`, `.blue`.
  - `PieceSetID`: staunty, cardinal, maestro, cburnett.
- **Tests:**
  - tap own piece selects it with targets
  - tap a target moves
  - tap another own piece reselects
  - tap during the opponent's turn queues a premove
  - user arrows toggle
  - the lastMove highlight is set from the history
- **Commit:** `M1: board interaction model`

### Task 8: GameController (Play orchestration)
- **Interface:** `@MainActor @Observable final class GameController`. Inputs: `PlayConfig(opponent: .maia(1100) | .stockfish(level), userColor: white|black|random, timeControl)`, plus `bot`, `telemetry`, `store`, `sounds: SoundSink` (protocol, so tests use a fake) and a clock source. It exposes:
  - `session`, `interaction`, `annotations`, `clock`, `phase` (`.userTurn | .botThinking | .over(GameResult)`), `viewPly` (for ◀ ▶ browsing)
  - `userTap/userDrop`, `choosePromotion`, `resign`, `offerDraw` (the bot accepts only if Stockfish eval within ±0.5 and move ≥ 30), `flip`, `stepBack/Forward`
  - `start()`, which plays gameStart and asks the bot to move if the bot is White
  - after the user's move: sound, clock press, bot task, bot move, sound, then premove auto-play if still legal
  - on game over: gameEnd sound, PGN saved to `GameStore`, telemetry `game.end`
- **Tests** (fake bot and fake sound sink, injected clock):
  - user move triggers a bot reply
  - the sound sequence is correct
  - a checkmate ends the game and saves the PGN
  - premove executes after the bot's reply
  - flag ends the game
  - resign
  - browsing back doesn't allow moves
  - every phase transition emits a telemetry event
- **Commit:** `M1: GameController`

### Task 10: Assets: pieces + sounds
- **Pieces:** SVGs from lichess-org/lila `public/piece/{staunty,cardinal,maestro,cburnett}` go into the asset catalog as `<set>/<color><kind>` (e.g. `staunty/wN`) with Preserve Vector Data. Licenses are recorded in `ChessCoach/Resources/LICENSES.md`.
- **Sounds:** generated with a Python script (`scripts/make_sounds.py`, numpy) as synthesized wooden clicks (filtered noise burst + resonant body) for move, capture (louder, two layers), castle (two clicks), check (click + high ping), promote (rising chime), illegal (low thud), premove (soft tick), gameStart and gameEnd (two-note chime), lowTime (tick). All are our own, so there are no licensing concerns.
- **Commit:** `M1: piece sets + generated sounds`

### Task 11: BoardView + PromotionPicker + SoundPlayer

- `SoundPlayer: SoundSink` uses a preloaded AVAudioPlayer pool and `.ambient` audio session. Haptics: light on move, medium on capture.
